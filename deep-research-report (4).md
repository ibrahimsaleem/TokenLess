# Token Optimization for AI Coding: Executive Summary

Token optimization means carefully managing the number of tokens (pieces of text) sent to AI models. This matters because large language models have finite context windows (e.g. Claude Sonnet ~200K tokens, GPT-4 up to 128K–400K tokens)【49†L65-L74】. If an AI agent’s context is overloaded with irrelevant instructions, tool definitions, or conversation history, performance degrades: response latency rises (GPT-4 can add ~2.4 seconds for each extra 10K input tokens【49†L117-L121】) and the model may hallucinate, drop earlier context, or miss details【49†L123-L131】.  

For enterprise teams, token efficiency directly impacts **cost, speed, and quality**. Every extra token costs money (e.g. Anthropic’s Claude Haiku is \$1 per million input tokens versus \$5 for Claude Opus【46†L169-L174】). Slower responses frustrate developers and can delay CI pipelines. And if the model loses track of requirements due to a full context, it may produce incorrect code or require reruns. By optimizing prompts and context, teams reduce API bills, get faster replies, and maintain high-quality outputs. 

In practice, this means trimming unnecessary content from prompts, caching static instructions, breaking tasks into focused steps, and routing simpler tasks to cheaper or smaller models. The rest of this guide explains **core concepts** (tokens, context windows, billing), **general techniques** (prompt compression, retrieval, compaction), **tool-specific best practices** (for Copilot, Windsurf, Claude Code, IDE extensions, APIs), relevant **MCP servers and utilities**, and resources like case studies, tools, and cheat sheets.

# Core Concepts 

- **Tokens:** Atomic pieces of text used by LLMs (roughly 3–4 characters). Billing is per token. E.g. GPT-4 Turbo charges per 1,000 tokens; Anthropic bills input tokens (10% cost if cached) and output tokens (full cost)【43†L315-L322】【45†L56-L60】. 
- **Context Window:** The maximum tokens an LLM sees at once. Claude Opus and Sonnet offer up to ~1M tokens; Claude Haiku ~200K (with 64K output)【46†L177-L179】. OpenAI’s GPT-4 comes in 8K and 32K variants (and up to ~128K for specialized models). Going over the window causes truncation. 
- **Input vs Output Tokens:** Inputs (prompt tokens) and outputs (completion tokens) are counted separately for billing. Anthropic caches repeated input tokens (at 10% cost) and they **do not** count against rate limits【43†L315-L322】. OpenAI does not cache prompts by default; all tokens count equally. 
- **Prompt vs Completion:** “Prompt” tokens include system messages, user messages, tools definitions, context, etc. “Completion” tokens are generated by the model. Keeping prompts concise and relevant maximizes the budget for outputs. 
- **Billing and Rate Limits:** Different models have different pricing and limits. For example, Claude Opus 4.7 costs \$5 per million input tokens, whereas Claude Sonnet 4.6 is \$3 (input)【46†L169-L174】. Claude’s rate limits treat cached tokens leniently: only uncached input tokens count toward requests-per-minute, so using prompt caching can dramatically increase throughput【43†L315-L322】. GitHub Copilot and other hosted models have their own rate limits and quotas (often hidden) and may charge per usage or subscription. 

# Token Optimization Techniques (General)

- **Prompt Compression & Summarization:** Rewrite verbose prompts into concise instructions. For example, replace long descriptions with bullet points or abbreviations. Use short system messages. Keep example ("few-shot") prompts minimal. If the same instructions repeat, save them in a system prompt or external memory. 
- **Few-Shot vs Zero-Shot Tradeoff:** Using examples (few-shot) improves accuracy but costs tokens. Use as few examples as necessary, or rely on the model’s knowledge for one-shot/zero-shot when possible. Few-shot is best when the task is unusual; otherwise prefer concise instructions. 
- **Chunking Strategies:** For large inputs (e.g. documents or code), break them into chunks. Process sequentially or with sliding windows. In generation tasks, generate in parts. This avoids hitting context limits. 
- **Retrieval-Augmented Generation (RAG):** Instead of sending all knowledge to the model, index your data (codebase, docs, Q&A) and retrieve relevant chunks. For example, use vector embeddings or semantic search to fetch top-k passages. This dramatically reduces tokens: e.g. one developer’s “agent OS” setup used semantic search to cut token use by ~91% compared to brute-grepping code【59†L97-L104】. 
- **System Prompt Caching:** For APIs that support it (Anthropic Claude), use prompt caching to reuse static parts. For example, set a custom system prompt or tool definitions once, and cache them (Anthropic’s API can cache up to the first 100K tokens; cached tokens only cost 10% each【42†L595-L604】【43†L315-L322】). This means repeated calls with the same base instructions are much cheaper. 
- **Structured Output Formatting:** When expecting specific outputs (JSON, CSV, etc.), define a strict schema. This can avoid the model “fluffing” and reduce back-and-forth re-prompts. It may not save tokens directly, but fewer clarifications are needed. 
- **Model Routing/Tiering:** Use smaller, cheaper models for simple tasks. Anthropic’s tiers show a clear cost/speed/quality tradeoff: **Opus** (highest capability, \$5/\$25), **Sonnet** (middle, \$3/\$15), **Haiku** (fastest/cheapest, \$1/\$5)【46†L169-L174】. For routine code edits or sub-tasks, Haiku often suffices【45†L31-L34】. GPT-3.5 turbo (8K) can replace GPT-4 for many code completions at lower cost. Route complex architectural or multi-step reasoning to the big model, and simple tasks to small models. 
- **Session Management:** In chat or agent sessions, trim the history. If the context is saturated, use summarization or start a new session. Claude Code’s `/compact` command (or similar) lets the agent compress past dialogue into a summary, freeing space【26†L239-L247】. Use `/clear` or reset conversation between unrelated tasks to avoid carrying dead context【26†L230-L239】【62†L174-L181】.

# Toolchain-Specific Optimization

## GitHub Copilot

Copilot (VS Code or GitHub IDE) typically uses **semantic search and indexing** under the hood rather than blindly sending all open files. By default, Copilot agents automatically search your codebase (semantic search, grep, file search, etc.) to gather relevant snippets【33†L451-L460】【33†L461-L470】. The agent builds an index of your workspace (skipping `.gitignore`d or excluded files【35†L515-L523】) and uses tools like `#codebase` (semantic search), grep, and file read to answer prompts【33†L462-L470】【33†L476-L485】. 

- **Open Tabs / Files:** Only opened or selected text appears directly in the prompt. Other files are accessed via search tools, not by copying their entire content. That said, *manually adding context helps*: you can explicitly attach relevant files or snippets (e.g. Copilot Chat’s “Attach Context” or VS Code’s `#-mention`). But avoid keeping irrelevant files open, as Copilot Chat may include visible code. Microsoft’s docs advise: “open relevant files and close irrelevant ones” to minimize noise【11†L612-L620】.
- **Workspace Indexing:** Ensure Copilot’s indexing is up to date. When you work in VS Code, Copilot builds a semantic index in the background (via GitHub or Azure repos, or local indexing)【35†L545-L554】【35†L572-L581】. This means Copilot often fetches needed code from the index instead of loading entire files into prompt. If your workspace isn’t indexed yet, Copilot falls back to text/grep search, which is slower but still avoids sending everything【35†L625-L633】. Use the status bar indicator to check index build status.
- **Prompt Crafting:** Rather than writing broad questions, phrase prompts with specific code terms or file references【35†L585-L594】. For example, reference symbol names or paths to focus search. Use `#`-mentions for known context (e.g. `#chat`, `#artifact`, `#repoSearch`). The official guidance says: *“Be specific… use function/class names… add context manually (select code, reference files)…”*【35†L587-L594】. This steers the agent’s tools and reduces irrelevant retrievals.
- **Inline Comments:** When writing comments or TODOs for Copilot, include clear instructions or examples. E.g. `// Add error handling to the database module:` often yields better completions. Vague comments cause more back-and-forth edits. Use descriptive method names and docstrings so Copilot can infer intent without extra prompt. 
- **File and Tab Management:** If Copilot feels slow or your session hits limits, close older tabs or split work into separate windows to reduce loaded context. Each open file contributes to the internal workspace index, but too many can slow semantic searches. Focus Copilot on one area at a time. For Copilot Chat (with chat history), if irrelevant context accumulates, either clear it or start a new conversation【11†L612-L620】.
- **Model Awareness:** Copilot may use different underlying models (e.g. Claude Sonnet vs GPT-4) in chat or code completion. Smaller models are faster but less contextual. If using Copilot Chat, you can sometimes choose GPT-4o (extended context) for larger context at the cost of speed. Knowing when to switch models helps: use larger models only when tackling large refactors or multi-file edits.

## Windsurf (Cascade Agentic AI)

Windsurf’s Cascade is an **agentic AI** that uses RAG and rules to manage context. Key points:
- **RAG-based Context:** Cascade automatically retrieves relevant code from your project via a retrieval engine (called M-Query)【13†L107-L116】. By default it indexes the entire codebase (excluding gitignored files) and fetches only pertinent snippets along with your current file and open files【13†L136-L145】. This means you don’t have to send the whole repo as prompt; Cascade uses semantic search on demand. For enterprise, enabling “Pro” features can expand context length and indexing.
- **Cascade Workflow:** In planning mode, Cascade builds a todo plan before executing. This lets you correct its plan early, preventing unnecessary file reads【62†L140-L149】. Use Cascade’s **plan mode** (prefix prompts with “write a plan” or similar) to verify steps. Fixing a plan is cheaper than undoing executed work. 
- **Project Rules (`.windsurfrules`):** Windsurf supports a `~/.windsurf/global_rules.md` and a workspace `.windsurfrules` for project-specific rules【15†L191-L195】. Use these to encode stable project facts (e.g. coding standards, architecture) that Cascade should always remember. Keep rules concise (workspace rules up to ~12,000 characters per file). This means Cascade doesn’t need to rediscover these facts, saving tokens in each session.
- **Auto-Memories:** Cascade can auto-generate “memories” from conversations (notes about your project). Importantly, creating or using auto-generated memories **does not consume API credits**【15†L173-L179】. When Cascade encounters new info, it can store it locally. It will then automatically load those memories when relevant. This offloads persistent context out of the immediate token budget.
- **Context Awareness Controls:** Windsurf provides features like *“Fast Context”* and *“Windsurf Ignore”* (from docs) to control what parts of your code it should send or ignore. Use these to limit context. For example, mark large non-essential files to ignore, so Cascade won’t pull them into prompt.
- **MCP Integration:** Windsurf supports the Model Context Protocol. You can hook in various MCP servers (e.g. a knowledge base, search APIs, or the Claude memory API)【16†L175-L183】. However, each MCP tool adds tokens to Cascade’s context by default (only tool names until used)【26†L259-L268】. Disable any unused MCP servers to save tokens. Prefer built-in CLI tools (e.g. `gh`, `aws`) when possible, since they don’t bloat context with definitions【26†L259-L268】.
- **Structuring Projects:** Organize your project with a clear hierarchy and CI/CD integration. Windsurf’s Cascade can natively interact with file system, but large monolithic repos can still slow it. Use `.windsurf/` directory for configs/rules and keep code modular to make retrieval efficient. 

## Claude Code (Anthropic’s CLI Agent)

Claude Code is Anthropic’s command-line AI assistant, which has built-in context and memory features:

- **CLAUDE.md (Persistent Context):** Claude Code loads a `CLAUDE.md` file (if present) at the start of each session as context【23†L128-L136】. Use CLAUDE.md to encode project-specific instructions (architecture, coding style, business logic) so the agent doesn’t have to rediscover them. For example, list APIs, libraries, or constraints. A well-crafted `CLAUDE.md` reduced one developer’s token usage by ~20%【60†L69-L78】. Keep it up-to-date and concise (Anthropic suggests under a few thousand words) to avoid consuming too much context.
- **Scoping Tasks:** Instead of telling Claude to “work on the whole project,” break tasks into focused subtasks. For instance, spawn a subagent for “Test the payment module” rather than a general “fix bugs” prompt. Subagents (spawned via skills) start with fresh context plus inherited CLAUDE.md, so they don’t carry unrelated history. In Claude Code, agent teams spawn separate windows per teammate【26†L198-L207】; similarly, use subprocesses for distinct tasks to avoid a single context growing too large.
- **Subagents:** Claude Code’s subagents can have their own memory and configuration【22†L1-L3】. Assign trivial sub-tasks to smaller models (Haiku or custom) and complex planning to Sonnet/Opus. For example, have a subagent run tests or linting under a `model: haiku` setting【26†L252-L256】. Remember each subagent has its own context window and costs tokens; keep them minimal. The Claude docs emphasize keeping agent spawn prompts focused (subagents load CLAUDE.md and tools automatically, but any extra text in the spawn prompt consumes context)【26†L200-L210】.
- **Token-Saving Flags:** Use the built-in `/compact` command to summarize conversation history when context grows【26†L239-L247】. You can customize what to preserve during compaction by adding instructions in your CLAUDE.md (e.g. “When compacting, focus on code changes and test results”)【26†L239-L247】. Also, use `/memory` to inspect what Claude remembered. Regularly use `/clear` between unrelated tasks to drop old context【26†L235-L243】.
- **Memory Features:** Claude Code automatically accumulates *auto-memory* (notes) in a `~/.claude/projects/.../memory/` folder【24†L139-L147】【24†L151-L159】. The `MEMORY.md` index file has a hard limit (only first 25KB/200 lines are loaded each session【24†L139-L147】) to prevent overload. You can manually edit or prune these memory files if too verbose. The memory tool in the API (MCP) is essentially the same feature, letting Claude store useful findings (build commands, debugging tips) outside the context window【47†L185-L193】.
- **Rate/Quota Management:** Use the `/usage` command in Claude Code to monitor tokens【26†L235-L243】. Claude Code will show session token counts and estimated cost (for API users). This helps identify wasteful prompts. Also note Anthropic recommends rate limit settings per team size (tokens-per-minute) to avoid spikes【26†L171-L180】.
- **Model Choice:** By default, Sonnet handles most coding tasks well at moderate cost【26†L252-L256】. Save Opus for very complex reasoning or multi-step planning. For CLI and pipeline tasks, Haiku is ideal (it’s fast and cheap【45†L31-L34】). You can switch models mid-session with `/model claude-haiku-4-5-20251001` for example. 
- **Compact/Streaming:** Claude Code supports streaming output (like Copilot) to reduce perceived latency, but this doesn’t save tokens. The `max_tokens` parameter (in API mode) does control output length. In chat mode, specify message length in your prompt if needed (“briefly explain in 50 words”). 
- **Cost Tips:** Reduce tool/plugin overhead – e.g. disable unused tools or MCP servers in `settings.json`【26†L259-L268】. Install code intelligence plugins (TypeScript server, Python language server) so Claude can navigate symbols instead of reading entire files【26†L273-L279】.

## IDE Extensions (VS Code, Cline, Continue, etc.)

Apart from Copilot, other AI coding extensions interact similarly with tokens:

- **Open Tabs & Files:** Most VS Code AI extensions (Copilot Chat, Cline, Continue, etc.) either rely on a server-side index (like Copilot) or send local content through an API. For example, Cline (Claude-based) *analyzes file structure and AST* and “carefully manages what info is added to context” so it can work on large projects without flooding tokens【36†L449-L457】. The extension typically reads only relevant files (via regex or AST) instead of sending the whole workspace.
- **Workspace Indexing:** Some extensions build their own indexes. As shown for Copilot, VS Code Copilot maintains a semantic index of the workspace【33†L451-L459】【35†L545-L554】. Cline likely does similar on install. Ensure these indices are up to date (e.g. sign-in on GitHub so Copilot can index repos, or rebuild semantic index from command palette【35†L564-L572】).
- **Tab Management:** Keep fewer tabs open to reduce the load on any extension that auto-includes open file content. If an extension exposes its context budget (e.g. Cline shows token usage per task【36†L481-L489】), use that to guide you. For Copilot Chat, remove or detach large editor contexts when not needed【11†L612-L620】.
- **Prompt Files:** Extensions like GitHub’s support “prompt files” or custom instructions files【29†L65-L72】. Use these to store common directives instead of repeating them in the chat.
- **Model Switching:** Tools like Cline let you choose the underlying model (Anthropic, OpenAI, local LLM). Match model size to task. For instance, in Cline you might configure a local 7B model for simple fixes, reserving Claude Sonnet or GPT-4 for high-level planning.
- **Local Agents vs API Agents:** Some extensions (like Continue or VSCode’s built-in agent feature) may run local LLMs (which typically have smaller context windows, e.g. 8–16K). When using local models, carefully constrain inputs to avoid overflow. For example, Continue supports pipelining tasks to a local model and remote model as needed (like the “agent OS” approach【59†L97-L105】). This splits context and saves tokens on the remote end.
- **Workspace Trust & Privacy:** Some AI extensions send file content to their service. While not directly token-related, ignoring irrelevant or private folders (via `.gitignore`, VSCode `files.exclude`, or the extension’s ignore settings) prevents unnecessary data leakage and token use.

## Anthropic/OpenAI API Usage

When building custom apps with LLM APIs embedded:

- **System Prompt Design:** System messages set behavior. Keep them as brief as possible while covering essentials. For multi-request sessions, you can cache a static system prompt (Anthropic’s API allows caching system prompts【42†L609-L618】). Avoid re-sending large instructions each request. For OpenAI, you might store a system message on your end and prepend it manually. Trim anything not needed for every call (e.g. elaborate mission statements).
- **Prompt Caching (Anthropic):** Use Anthropic’s prompt caching feature to “freeze” static content (system messages, repeated instructions) in memory【42†L595-L604】. Once a cache entry is created (minimum length requirement), subsequent calls with that content are much cheaper. Monitor cache hits via the API fields (`cache_read_input_tokens`)【42†L685-L694】. Align repeated content (like tool definitions, long documents) so they consistently hit the cache.
- **API Streaming:** Enable streaming output to get tokens as they are generated (for responsive UIs). Streaming doesn’t save tokens, but it improves perceived latency. However, streaming results do count against rate limits as output tokens. You can also use the OpenAI Chat API’s `max_tokens` parameter to bound the response length. For Anthropic, the `max_tokens_to_sample` (or similar) caps completion length.
- **History Management:** In conversational APIs, carefully manage history. Keep only the last N turns or summarised context. For Claude API, consider using the `countTokens` endpoint to check if your accumulated messages fit in the model’s window【52†L194-L202】. In OpenAI Chat, when history grows, you may need to drop earlier turns or summarize them yourself.
- **Model Selection (API):** Choose the model tier fitting your task. For Anthropic: use *Haiku* (fast, cheap) for routine tasks or high-concurrency scenarios, *Sonnet* for general tasks, *Opus* for the hardest reasoning【46†L169-L178】. For OpenAI: use GPT-3.5-turbo for general coding (8K context), upgrade to GPT-4 for complex design, and GPT-4o/32K if you need more context. Always test if a smaller model suffices before using an expensive one.
- **Rate and Batch Tuning:** Use batching or multi-turn API calls where possible. Anthropic offers a Message Batches API for efficient throughput. Turn on the Anthropic Console’s usage dashboard or OpenAI’s usage endpoint to track token spend (e.g. [43†L327-L335]). Tools like LangSmith or Helicone can instrument prompts for debugging and monitoring.

# MCP Tools & Servers

The **Model Context Protocol (MCP)** ecosystem provides servers (tools) that agents can call to fetch data or perform operations. Each MCP server typically adds its name/description to the agent’s prompt, so unused ones waste tokens. Key tools:

- **Claude Memory Tool:** As documented, this tool lets Claude Code store/retrieve files in a `/memories` directory【47†L185-L193】. It functions like an external memory database. With MCP, you can call `memory.view`, `memory.update`, etc. This offloads persistent context (e.g. project notes) outside the prompt. 
- **Knowledge/FAQ Servers:** Tools like a Wikipedia or FAQs API server (some MCPs exist for knowledge search). If your code references standard libraries or compliance rules, an MCP that answers such queries can avoid including those docs in context.
- **Vector DB or Embedding Retrieval:** MCP servers for vector search (e.g. Pinecone, Weaviate, or local embeddings) can retrieve relevant docs. For example, OpenAI’s `text-embedding-003` with an MCP connector. These let the agent ask “find similar text in this database” instead of storing it in prompt. 
- **GitHub or Code Search:** The GitHub MCP server 【33†L508-L510】 allows agents to query repos, issues, etc., beyond local workspace. For Windsurf/Copilot, an MCP might fetch code from other projects or docs.
- **Custom CLI/DB tools:** Any local CLI can be exposed as an MCP (Cascade supports integrating `gh`, `aws`, custom scripts). These don’t consume prompt tokens (CLI runs separately). For example, configure an “Inventory” MCP for your API docs. Windsurf’s docs recommend using CLI tools over MCP definitions where possible, since CLI tools don’t require listing in prompt【26†L259-L268】.
- **MCP Proxy or Hub:** The official MCP repo lists multi-purpose servers (Discord, Slack, custom HTTP endpoints)【19†L449-L458】. If your team has internal data stores or APIs, you can deploy MCP wrappers to let Claude/Copilot query them without manual prompt includes.
- **MCP Scaling Tools:** Tools like “LiteLLM” or others help with context offloading. For example, connecting a SQL database via MCP to answer questions about company data. 

When adding MCP servers:
- Audit them regularly. The context cost can be 10–30K tokens per tool just for definitions【49†L97-L104】. Only enable servers actively used for the task. In Claude Code, use `/mcp` to list and disable idle servers【26†L259-L268】. 
- For Windsurf/Cascade, you add MCPs in `.windsurf/config.json` or via the Marketplace. Each tool’s definition appears in prompts. Use deferred tools (only name until called) to minimize impact. 
- Consider writing custom MCPs for common operations: e.g. a “Dependency Graph” tool to supply relevant file paths (similar to Nicola Alessi’s approach【60†L123-L132】), or a “Code Summary” tool that returns short summaries of files. These can replace heavy agent work.

# Token-Optimization Tools & Platforms

Several tools help measure and reduce tokens:

- **Prompt Engineering/Optimization:** 
  - **LangChain** (open-source) – while known for chains, it has utilities for prompt debugging and caching, and LangSmith (formerly Promptio) for monitoring. 
  - **DSPy** – a research toolkit for automatically finding shorter prompts (via search over rewrite strategies)【50†L1-L9】.
  - **PromptLayer** – API for logging and analyzing prompts across calls (with caching options).
  - **PromptFoo / PromptPerfect** – libraries to lint and optimize prompts. Not APIs per se, but useful for experimentation.
  - **HumanLoop** – provides tools for building and iterating on LLM prompts with human feedback.
- **Token Counting:** 
  - **tiktoken** – OpenAI’s Python/JS library to count tokens for ChatGPT models. Widely used for pre-flight checks. 
  - **Anthropic token counter API** – their official `messages.countTokens` (or SDK) returns exact counts for any Claude request【53†L125-L134】. Use this to validate before sending.
  - **liteLLM** – a small Python library that wraps provider APIs (including Anthropic, OpenAI, Vertex) to get exact token counts in a unified way【51†L8-L12】.
  - **Local approximators:** If you need offline estimation, use OpenAI’s tiktoken with the `p50k_base` encoding (anthropic models) or appropriate encoder for other providers【53†L133-L142】.
- **Usage Monitoring:** 
  - **Helicone** – a proxy/monitor for LLM queries (especially OpenAI) to visualize token usage and responses. (Be cautious of privacy/security.)
  - **LangSmith** (by LangChain) – for tracking prompt performance, token usage, examples.
  - **OpenMeter** – an open-source LLM usage tracker by Merico for companies.
  - **Anthropic Console** – official dashboard showing usage by model, rate-limit and spend【26†L153-L161】.
  - **Cloud Providers:** If using Claude via AWS Bedrock or GCP, their billing dashboards can show usage.
- **Open-Source Repos:** Active GitHub projects for token-saving:
  - **PromptChainer** – tools for dynamic prompt assembly.
  - **Mistral/Torch** related? Possibly less relevant.
  - **Workspace analyzers** – e.g. Nicola Alessi’s `vexp` (dependency graph).
  - **Academic libs:** e.g. `transformers` library has some token counting and data collators.
  - Search GitHub for “prompt optimization” or “context window” for emerging tools.

# Competency Framework

Define skill levels for token optimization:

- **Basic (Novice):**  
  - Understand what a token is and that models have context limits.  
  - Can count tokens (e.g. using a simple tool) and read API docs for token pricing.  
  - Follows simple best practices: writing concise prompts, closing irrelevant files, and using smaller models for straightforward tasks.  
  - Knows to “clear” or restart chats between unrelated tasks.  
- **Advanced (Intermediate):**  
  - Actively uses token-counting tools (tiktoken, API counters) to budget prompts.  
  - Writes effective system messages and `CLAUDE.md`/prompt files.  
  - Applies compression: uses summarization commands (`/compact`) or manual summarization to shorten history.  
  - Designs prompts with one-shot or few-shot examples only when needed.  
  - Splits tasks into subagents or steps to limit context growth.  
  - Routes tasks to appropriate model tier (e.g. testing vs planning).  
  - Utilizes prompt caching features (Anthropic’s cache, LangChain caching).  
- **Expert (Pro):**  
  - Routinely analyzes context breakdown (using `/context` in Claude Code or debug tools) to find overhead sources.  
  - Implements RAG pipelines: sets up vector DBs, retrieval tools (e.g. with Windsurf or LangChain) to avoid sending raw data.  
  - Develops custom MCP servers or CLI wrappers to offload knowledge (e.g. a curated codebase search tool, vector knowledge bases).  
  - Monitors token spend across projects (via Anthropic Console, LangSmith) and enforces best practices org-wide.  
  - Trains or fine-tunes smaller models for repetitive tasks to cut calls to big LLMs.  
  - Contributes to internal guides: teaches others to write high-quality prompts and perform context audits.

# Real-World Examples & Case Studies

- **Dependency-Aware Prompting:** Nicola Alessi (DEV community) cut a Claude agent’s tokens by ~74% on a 200-file project【60†L139-L148】. Key moves: writing a *specific* `CLAUDE.md` with project decisions (saving ~20% tokens)【60†L69-L78】, and supplying a precomputed dependency graph so the agent only read ~5 relevant files instead of 40【60†L131-L140】. This led to answers with the same info in 2,140 tokens vs 8,247 tokens before – a 74% reduction【60†L139-L148】.  
- **Agent OS for Efficiency:** On Reddit, a developer described an “agent OS” that routes easy tasks to a small local model (Ollama 14B) and reserves Claude for hard tasks【59†L97-L105】. By preventing the agent from re-reading the whole codebase and cold-starting each session, they saw a **68.5% overall token reduction**. For example, using semantic search instead of brute-force grep cut one sub-task’s tokens by 91%【59†L97-L104】. This shows how hybrid agent architectures can save massive tokens.  
- **Copilot Optimization:** Practitioners note that simply choosing the right model in Copilot Chat matters. Anthropic found (and a GitHub manager reports) that Claude Haiku provides near-Sonnet quality for code but with much lower latency and cost【45†L31-L34】【60†L55-L61】. A Medium post (Sai Komal Pendela) highlights that using lighter Claude models for routine coding makes Copilot faster and less verbose.  
- **General LLM Usage:** Companies using Claude or GPT have reported success with prompt caching and batching. One Anthropic blog notes prompt caching can yield *up to 90% savings* on frequent prompts【45†L56-L60】. Others have published on LangSmith and Helicone showing how context trimming improved throughput for chatbots and support agents. While not code-specific, these lessons apply: e.g. document summarization before sending to the model, or deleting old QA pairs from history.

# Quick Reference Cheat Sheet

**For each tool, follow these top practices:**

- **Copilot (IDE):**  
  1. **Open only relevant files.** Close others to limit context【11†L612-L620】.  
  2. **Use semantic search cues.** Reference code terms in prompts and use `#-mentions` to add context【35†L587-L594】.  
  3. **Write clear comments.** Be specific in inline prompts (function names, tasks) to avoid back-and-forth.  
  4. **Split tasks.** Break big tasks into steps; start new chat for unrelated work.  
- **Windsurf (Cascade):**  
  1. **Plan first.** Use Cascade’s plan mode (or prompt it to outline steps) before acting【62†L140-L149】.  
  2. **Use .windsurfrules and memories.** Put stable info in rules, let memories accumulate dynamic context (no token cost)【15†L123-L132】.  
  3. **Leverage retrieval.** Trust Windsurf’s RAG engine to fetch only necessary code【13†L136-L145】. Provide hints (keywords) if needed.  
  4. **Limit MCP tools.** Only enable needed servers; prefer CLI commands over heavy MCP definitions【26†L259-L268】.  
- **Claude Code:**  
  1. **Create a precise CLAUDE.md.** List actual project specifics (auth method, frameworks, file locations) not vague descriptions【60†L69-L78】.  
  2. **Use /compact and /clear.** Summarize context after each phase (`/compact`), and clear the session between unrelated tasks【26†L239-L247】【26†L235-L243】.  
  3. **Spawn subagents.** Delegate subtasks to new agents (with focused prompts and, if trivial, to Haiku) so each has fresh context【26†L250-L256】.  
  4. **Monitor with /usage.** Regularly check token usage and trim overhead (e.g. disable idle subagents).  
- **API (Anthropic/OpenAI):**  
  1. **Cache static content.** For Claude API, mark repeated system messages to use prompt caching【42†L595-L604】. For ChatGPT API, reuse system/user messages or use caching layers.  
  2. **Trim history.** Limit conversation history to the last few turns or summarized blocks. Remove irrelevant old chats.  
  3. **Choose right model.** Start with cheapest model that can do the job (e.g. Claude Haiku, GPT-3.5); move up only if needed.  
  4. **Set max_tokens.** Bound output length to what you need (less wasted generation). Use streaming for responsiveness (without loss of tokens).  
- **General Tips:**  
  1. **Count before sending.** Use tiktoken or provider token-count APIs to check prompt length. Adjust if near limits【52†L194-L202】.  
  2. **Avoid redundancy.** Don’t resend instructions already implied or stored.  
  3. **Use RAG for large data.** Keep big docs or corpora in a database/vector store and retrieve as needed.  
  4. **Monitor & audit.** Set up cost/usage alerts (Anthropic Console, Helicone) to catch runaway token use.
